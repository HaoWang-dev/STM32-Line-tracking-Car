# STM32-Line-tracking-Car
## 前言
这是一个基于 STM32 的智能循迹避障小车，系统以 STM32 为主控，具备循迹和避障功能。循迹部分用的是 PID 循迹算法，会根据传感器采集到的偏差实时调节电机输出，从而实现轨迹跟踪。这个小车是我大二的时候做的。这几天电脑内存告急，整理文件时把当时的小车资料翻了出来，想了想，索性就直接开源了。其中 PID 循迹环的代码是我当时自己写的。那会儿我看网上很多演示视频，人家的循迹小车跑得特别丝滑，再看看自己的小车，还在一卡一卡地往前蠕动。后来我也上网找过开源代码，各种论坛翻了一遍，也没找到开源的，索性就自己写了一个。实测下来效果还不错。后来在 2026 年全国大学生电子竞赛里又用上了这个算法，最后拿到了省级一等奖，这个算法确实功不可没。当然，毕竟是自己写的，肯定不是十全十美，我相信以后还会有更厉害的算法出现。

## 代码架构
本项目基于 STM32Cube 生态进行开发。开发过程中，使用 STM32CubeMX 完成 MCU 外设配置与初始化代码框架生成，并在 STM32CubeIDE 中编写和调试各模块驱动代码。项目已提供完整工程文件，可直接使用 STM32CubeIDE 打开，无需额外搭建工程环境，便于快速编译、下载与调试。
### 
整个工程的代码做了模块化处理：一来方便在不同项目之间移植，二来调试效率更高，代码也能更简洁。PID 底层代码是我当时学了江协科技的 PID 教程之后，又自己改了改，最后归纳成了独立的 PID 代码文件；OLED 部分则直接沿用了江协的源码。当然，重点不在这儿。在 GW 代码文件夹里，藏着一个看起来平平无奇的函数，那才是循迹环的核心，精华中的精华，下面重点介绍一下。
###                                                  
### float calc_error(char Data[8], int8_t weight[8])
### {
###     int32_t sum_weight = 0;
###     int32_t active_count = 0;
### 
###     for (uint8_t i = 0; i < 8; i++)
###     {
###         if (Data[i] == '0')
###         {
###             sum_weight += weight[i];
###            active_count++;
###         }
###     }
###     if (active_count == 0)
###     {
###         return -75;
###     }
### 
###     return sum_weight;
### }
核心逻辑说白了就是“按位置给分”：八个循迹通道，每一位都有自己的误差数值，从中间往两边数值依次加大。然后每次轮询八个 GPIO，谁检测到黑线，谁就把自己的误差数值贡献出来，最后把总数值一加，得到的结果直接送去参加 PID 调控。
### 
对，精髓就在这儿：把扫到黑线的那几位对应的误差数值直接相加。小车没偏航的时候，左右两边贡献的误差正好抵消，加起来就是 0，PID 自然就不去调控；一旦偏了，总和就不为 0，PID 才开始修正。这样就巧妙地做出了一个“死区”效果，小车在直道上不会来回抖。
### int8_t err_weight[8] = {-35, -25, -15, -5, 5, 15, 25, 35};
当然，误差数值要一半正一半负，不然循迹环就不适用了。
### 
当循迹模块一个黑线都没扫到时，我的处理方式很简单粗暴——直接朝一个方向“打死”。这招在正方形赛道上特别好使；就算不是正方形赛道，也能起到一种防御性编程的效果，至少不至于让小车当场“放飞自我”。
###
其余的代码逻辑说白了也不复杂：没有障碍物的时候，PID 接管小车；一旦检测到障碍物，就切到开环避障；避完再切回 PID。整体就是这么个来回切换的逻辑，应该不算绕。
